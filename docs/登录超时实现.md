# 登录超时（空闲自动登出）实现文档

> 适用版本：v1.43.11+（当前实现）。本文描述「人离开页面后自动退出登录」的完整机制：服务端会话模型、滑动续期规则、前端心跳策略、全局 401 兜底，以及踩过的坑。

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 空闲自动登出 | 用户无操作满 TTL 后会话失效，重新进入页面需登录 |
| 操作不被误踢 | 用户持续操作期间绝不登出（哪怕一直开着页面） |
| 后台轮询不续命 | 页面挂着时 Dashboard 每 3s 轮询、SSE/WS 心跳都**不能**维持会话 |
| 服务端权威 | 登出判定只由服务端 401 触发，前端不做本地计时 |
| 重启不丢会话 | 服务重启 / OTA 升级后会话按原到期时间恢复 |

---

## 2. 总体架构

```
┌─────────────── 前端 (App.tsx) ───────────────┐      ┌──────────────── 服务端 (auth.ts) ───────────────┐
│                                              │      │                                                 │
│  真实用户活动(mousemove/keydown/…)            │      │  Map<tokenHash, {userId, expiresAt}>            │
│    → 节流 30s/次 → GET /api/auth/me ─────────┼──────→  renewSession(): 滑动续期（唯一续期入口）          │
│                                              │      │                                                 │
│  setInterval 60s → GET /api/auth/ping ───────┼──────→  peekSessionUser(): 只读探活、不续期             │
│                                              │      │                                                 │
│  业务请求/轮询/SSE/WS ────────────────────────┼──────→  requireAuth → getSessionUser(): 只读、不续期    │
│                                              │      │                                                 │
│  任意响应 401 → 派发 auth:unauthorized ───────┼──────→  401 JSON {error:"未登录或会话已过期"}            │
│    → App 监听 → 回登录页                      │      │                                                 │
└──────────────────────────────────────────────┘      └─────────────────────────────────────────────────┘
```

**核心原则：三类会话校验函数，只有 `/api/auth/me` 走续期**

| 函数 | 续期? | 使用方 |
|---|---|---|
| `renewSession()` | ✅ 滑动续期 | 仅 `GET /api/auth/me`（前端真实活动节流调用） |
| `getSessionUser()` | ❌ 只读 | `requireAuth` 中间件 → 所有业务请求、后台轮询、WS 握手 |
| `peekSessionUser()` | ❌ 只读 | 仅 `GET /api/auth/ping`（前端 60s 探活） |

## 3. 服务端实现（`server/auth.ts`）

### 3.1 会话存储

- 内存 `Map<tokenHash, Session>`，键为 token 的 **SHA-256 摘要**（内存与落盘均无明文 token）
- 持久化到 `<data>/sessions.json`（`dataPath()`），模块加载时 `loadSessions()` 恢复，已过期的直接丢弃
- 落盘写节流 **5s**（`PERSIST_THROTTLE_MS`）：高频续期下避免每请求都写盘；重启最多丢 5s 滑动量

### 3.2 TTL

- 来源：`settings.user.sessionTimeout`（分钟），**默认 30**；最小钳制 1 分钟
- `sessionTtlMs()` 带 5s 内存缓存，避免每次请求读 settings.json
- 设置页保存时调 `invalidateSessionTtlCache()` 立即失效缓存（改动对**新登录会话**生效）

### 3.3 会话生命周期

| 阶段 | 行为 |
|---|---|
| 创建（登录成功） | `createSession()`：随机 32B token → 存摘要，`expiresAt = now + TTL`；Cookie `httpOnly + sameSite=lax + maxAge=TTL` |
| 空闲超时 | 会话创建时固定初始 `expiresAt`；**只有真实活动续期才滑动刷新**，无活动满 TTL 即过期 |
| 续期（`renewSession`） | `expiresAt = now + TTL`（只延不减：`newExpires > s.expiresAt` 才写） |
| 校验失败/过期 | 从 Map 删除 + 立即落盘，返回 null |
| 登出 | `destroySession()` 删单会话；`destroySessionsForUser()` 删某用户全部会话（账号重设后强制下线） |

### 3.4 相关端点（`server/index.ts`）

| 端点 | 走哪个函数 | 语义 |
|---|---|---|
| `POST /api/auth/login` | `createSession` | 登录并下发 Cookie |
| `GET /api/auth/me` | `renewSession` | **唯一续期入口**，由前端活动节流调用 |
| `GET /api/auth/ping` | `peekSessionUser` | 只读探活，过期返 401 |
| `POST /api/auth/logout` | `destroySession` | 主动登出 |
| 其余全部业务端点 | `requireAuth` → `getSessionUser` | 只读校验，401 = 未登录/已过期 |

## 4. 前端实现（`src/App.tsx` 心跳 effect）

`authState === "authed"` 时挂载：

### 4.1 活动监听 → 续期

- 监听 6 类真实用户事件：`mousemove / mousedown / keydown / pointerdown / wheel / touchstart`（全部 `passive: true`）
- `markActivity()` **节流 30s/次**（`lastRenew` 时间戳）：命中节流窗口才发 `GET /api/auth/me` 续期
- 30s 节流 < 30 分钟 TTL ⇒ 持续操作的用户每 ≤30s 被服务端滑动续期，永不被踢

### 4.2 低频探活 → 自动登出

- `setInterval` **60s** 调 `GET /api/auth/ping`（只读、不续期，不会自己维持会话）
- 会话真过期 → 服务端 401 → 全局兜底（见 §5）→ 回登录页
- 最坏登出延迟 ≈ TTL + 60s（探活周期）

### 4.3 刻意不做的设计

- **不用前端本地计时主动登出**：前端无法可靠感知服务端是否仍在续期，本地计时误判会导致「正在操作却被踢」。唯一登出触发条件 = 服务端 401（任意业务接口或 ping）。

## 5. 全局 401 兜底（`src/api.ts`）

所有 401 响应统一经 `notifyUnauthorized(url)` 处理：

```ts
const PRE_LOGIN_401_ENDPOINTS = ["/auth/login", "/auth/logout", "/auth/init-status", "/auth/init"];
// 命中预登录端点 → 不派发（登录失败本来就该停在登录页）
// 其余（含 /auth/me、/auth/ping）→ window.dispatchEvent("auth:unauthorized")
```

App 监听 `auth:unauthorized` → 清 `me` state → `setAuthState("login")`。

**覆盖全部通道**（这是设计难点，每条通道都要接线）：

| 通道 | 401 可见性 | 接线方式 |
|---|---|---|
| 普通 fetch 请求 | 可读 `res.status` | `request()` 内调 `notifyUnauthorized` |
| 文件上传/下载（fetch / XHR） | 可读状态码 | 同上 / onload 判断 401 后派发 |
| 长传 XHR（镜像推送等） | 可读 `xhr.status` | onload 401 → 派发 |
| **SSE（EventSource）** | **读不到 HTTP 状态码**（EventSource 特性） | 服务端对鉴权失败改发 **`200 + event: unauthorized` 帧 + end**，前端 `addEventListener("unauthorized")` 派发（v1.43.11） |
| WebSocket 握手 | 握手走 `getSessionUser`（只读），失败即拒绝连接 | 不续期即不影响超时语义 |

## 6. 配置入口

- **设置中心 → 用户 → 「会话超时（分钟）」**（`Settings.tsx`），提示文案：空闲超过该时长后需重新登录；改动在下次登录时生效
- 服务端默认值：`server/settings.ts` → `user.sessionTimeout: 30`

## 7. 历史坑与修复（重要经验）

| 版本 | 问题 | 根因 | 修复 |
|---|---|---|---|
| ≤v1.43.10 | 空闲超时半边不生效、页面挂着永不登出 | 业务轮询/心跳经 `getSessionUser` 之外的路径续命；前端靠本地计时+保活轮询续住会话 | 收敛为「三类校验函数」模型：续期只留 `/auth/me` 一个口 |
| v1.43.11 | 会话过期后用户停在页面上登不出去 | `notifyUnauthorized` 用 `!url.startsWith("/auth/")` 把**整个 `/auth/` 前缀**排除在派发外 ⇒ ping 的 401 被静默吞掉 | 改为仅排除 4 个预登录端点，`/auth/me`、`/auth/ping` 的 401 必须派发 |
| v1.43.11 | SSE 通道过期后无任何反应 | EventSource 拿不到 HTTP 状态码，onerror 无信息 | 服务端鉴权失败统一「200 + `event: unauthorized` 帧 + end」，前端监听该帧派发登出 |
| 历史教训 | 「正在操作却被踢」 | 前端本地计时 lastActivity 陈旧，而服务端仍在续期 | 废弃前端本地计时，纯服务端权威 |

## 8. 边界情况

| 场景 | 行为 |
|---|---|
| 页面挂着人离开 | ping 60s 一探；TTL 满后首个 ping 返 401 → 自动回登录页 |
| 持续操作 | 活动节流续期每 ≤30s 一次，永不登出 |
| 服务重启 / OTA | sessions.json 恢复未过期会话，按原到期时间继续计时 |
| 电脑休眠恢复 | 浏览器定时器恢复后下一次 ping 即检测（若已过期立即登出） |
| 多标签页 | 共享同一 Cookie 会话，任一标签页活动即续期（服务端无 per-tab 概念） |
| 账号重新初始化 | `destroySessionsForUser()` 作废全部会话，前端收 `403 REINIT_REQUIRED` 切向导 |
| settings.json 文件缺失 | TTL 回落默认 30 分钟 |
