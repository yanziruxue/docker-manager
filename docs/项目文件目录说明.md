# docker-manager 文件目录说明

> 项目：Docker Stack Manager（GitHub `yanziruxue/docker-manager`）
> 文档版本：**增量维护至 v1.32.0**（新增文件即登记，行数随之更新；未逐版全量复核）
> 目的：一张表看清「哪个文件干什么」，便于定位改动位置、避免误删运行时数据。

---

## 0. 顶层速览

```
docker-unraid/
├── src/                 前端（React + Vite + Tailwind）
├── server/              后端（Express + dockerode，tsc 编译到 server/dist）
├── scripts/             构建 / 发布脚本
├── deploy/              交付物（linux SEA 单文件 + docker 镜像）
├── docs/                文档（本目录）
├── public/              前端静态资源
├── config/              运行时配置目录（内容由程序生成）
├── data/                运行时数据目录（ stacks / users / 设置…）
├── logs/                运行日志（按天切分）
├── build-upload/        待发布的 zip 交付包
├── dist/                前端构建产物（vite build 输出）
└── node_modules/
```

**三句话概括数据流**

```
浏览器 → src/（前端 UI）
        → /api → server/index.ts（路由）→ server/docker.ts（Docker 操作）
        → /ws/terminal（终端）· /api/.../stream（SSE 资源监控）
后端把前端 dist/ 内嵌进 SEA 单文件二进制 → deploy/linux/*.zip → 服务器
```

| 文件 | 行数 | 作用 |
|---|---|---|

| `check-auth-render.mjs` | 157 | **账号 UI 渲染断言**（`npm run test:auth`，v1.31.0）：借 vite 自带 `esbuild` + `react-dom/server` 在 Node 里 SSR 渲**真身组件**，断言文案/属性/常量且**渲染期零 `fetch`** |
| `check-auth-wiring.mjs` | 277 | **账号接线断言**（`npm run test:auth`，v1.31.0）：TS 编译器 API 遍历源码，断言 `authState` 五态、事件派发/监听**跨文件配对**、分支顺序与常量 |
| `check-restart-wait.mjs` | 204 | **OTA 重启等待断言**（`npm run test:restart`，v1.31.1）：esbuild 打包 `src/lib/restart-wait.ts` → 桩 `fetch`/`window` → 5ms 轮询跑完 6 种探活序列（核心回归＝`403 REINIT_REQUIRED` 必须刷新）+ 接线契约 |
| `check-thermal.mjs` | 228 | **温度采集门禁**（`npm run test:thermal`，并入 `test:gates`，v1.35.8）：从 `server/docker.ts` 抽出 `readDiskTempC` / `readCpuTempC` / `isDrivetempLoaded` / `listWholeDisks` / `getThermalStatus` 的**真实函数体**（esbuild 去类型），用 `Object.create(fs)` 造**影子 fs** 只注入该 vm 模块的 `require`（**不改真实 fs**），在内存里构造虚拟 sysfs 树执行 ⇒ **15 项断言**：CPU 芯片优先级（coretemp>k10temp）/ `temp1_label` / `/sys/class/thermal` 回退 / NVMe 路径 / SATA+drivetemp 路径 / drivetemp 两种判定 / 分区·loop·dm 过滤 / 空 sysfs 不抛。**为什么必须独立存在**：温度只读 Linux `/sys`，Windows 开发机既无 `/sys` 也无 root，改坏只会显示「—」而**静默失败**；负向自检＝`milli/1000` 改 `milli/100` ⇒ 15→7、`exit 1` |
| `check-install-drivetemp.sh` | 183 | **安装脚本 drivetemp 门禁**（`npm run test:install`，并入 `test:gates`，v1.35.8）：从 `deploy/linux/install.sh` / `uninstall.sh` **按注释锚点抽出真实代码块**（不是复制一份，避免与实现漂移），把 `/etc/modules-load.d` 改写到工作区沙箱（`.tmp-install-check/`）。再用桩命令（`modinfo` / `modprobe` / `systemctl`）驱动 **7 种环境** ⇒ **34 项断言**：默认加载 + 持久化 / `--no-drivetemp` 跳过 / 模块不可用 / `modprobe` 失败 / 非 systemd 不写多余文件 / 无 `modprobe` / 卸载侧归属识别（只删带标记的 conf）。**核心不变量＝「绝不阻塞安装」**：`set -euo pipefail` 下每种环境都必须 `exit 0`。**为什么必须独立存在**：`install.sh` 要 root + systemd 才能真跑，Windows 开发机无法执行，改坏只在用户机器上暴露。两个坑：桩目录须 `cygpath -u` 转 POSIX（写 `D:/…` MSYS 不查找）、**只前置追加 PATH**（整段替换会把工具链 shim 挤掉而挂死）。负向自检＝「模块不可用」分支注入 `exit 7` ⇒ 34→33 / `exit 1`，还原后 34/0 |
| `publish-release.mjs` | 215 | 创建 GitHub Release（`gh` CLI），从 CHANGELOG 摘当前版本 notes |
| `push-via-api.mjs` | 131 | **走 GitHub API 推源码**（git 端口被墙时的替代方案） |
| `publish.sh` | 93 | 一键：构建 → 打包 → 发布 |
| `quick-install.sh` | 92 | 服务器一键安装脚本（随 Release 分发） |

## 8. 构建链路（改动涉及哪些文件）

```
① npm run build:frontend
   src/**  ──vite──▶  dist/                        （前端产物）

② node scripts/build-binary.mjs
   server/** ──esbuild──▶ deploy/linux/bundle.js   （后端单文件 bundle，含 dist 内嵌）

③ SEA 注入（跨平台，无需 WSL）
   原始 Linux node ──cp──▶ deploy/linux/docker-manager-yanzi
   node --experimental-sea-config  deploy/linux/sea-config.json
   npx postject  ... NODE_SEA_BLOB deploy/linux/sea-prep.blob

④ python deploy/linux/make-package.py
   ──▶ deploy/linux/docker-manager-yanzi-linux-x64.zip ──cp──▶ build-upload/

⑤ 发布：scripts/push-via-api.mjs（源码）+ scripts/publish-release.mjs（Release）
```

| **版本号唯一源是 `package.json`** | `vite.config.ts`（第 7 行）与 `scripts/build-binary.mjs`（第 19 行）都是 `JSON.parse(fs.readFileSync(package.json)).version` ⇒ **只改 `package.json` 的 `version` 即可**，`__APP_VERSION__` 三处自动一致；另外需手工同步 `docs/CHANGELOG.md`（及 `MEMORY.md` 版本状态行） |
| **`test:auth` / `test:restart` / `test:thermal` / `test:install` 不挂构建链** | `check-auth-render.mjs` + `check-auth-wiring.mjs`（账号）、`check-restart-wait.mjs`（OTA 重启等待）、`check-thermal.mjs`（温度采集，v1.35.8）与 `check-install-drivetemp.sh`（安装脚本 drivetemp 配置，v1.35.8）都是**特性作用域**的断言（将来重新设计 reinit / 更新流程 / 温度采集需同步改断言），挂进常驻构建链会变成长期摩擦；故以 `npm run test:auth` / `test:restart` / `test:thermal` / `test:install` 独立暴露，**改动账号 UI / 鉴权 / 更新链路 / 温度采集 / 安装脚本后手动跑**（一条命令跑全部：`npm run test:gates`）。`check-thermal.mjs` 额外注意：它**读 `server/docker.ts` 源码文本抽函数**，若把 `readDiskTempC` / `readCpuTempC` / `isDrivetempLoaded` / `listWholeDisks` / `getThermalStatus` 改名或移动，须同步改门禁里的锚点与符号校验（锚点失效时会直接 `exit 1` 报错，不会静默放过）。`check-install-drivetemp.sh` 同理**读 `deploy/linux/install.sh` / `uninstall.sh` 源码文本、按注释锚点抽块**，若把锚点注释（`# 配置磁盘温度传感器（drivetemp）` / `# 停止旧服务` / `# 删除安装脚本写入的 drivetemp 模块配置` / `# 删除 sudoers 授权片段`）改名或移动，须同步改门禁锚点（失效即 `exit 1`）。`lint:hooks` 则相反——**已挂在 `build:frontend` 之前**，违规直接中止构建 |
| **不能直跑 `server/dist/index.js`** | `BUILD_BINARY` 由 esbuild define 注入，直跑会 ReferenceError |
| **SEA 构建不要跑 `deploy/linux/build.sh`** | 它复制当前 `node`（Windows 版）作为基底；本环境 WSL 被安全策略拦截，必须走「原始 Linux node + postject」手动流程 |
| **`deploy/linux/新建 文本文档.txt`** | 历史遗留空文件，可安全删除 |
| **发布前确认** | 发布 Release 属于对外动作，执行前须向用户确认 |
| **勿提交** | `.env`、`data/`、`logs/`、`dist/`、`build-upload/`、SEA 中间产物（均已 gitignore） |
