# 安装量 / 活跃度上报 — 接口与上报内容速览

> **适用版本**：v1.35.11+ 语义（单字段 `upapi`；`install` 次数 ≈ 去重设备数）；**v1.50.10 起对齐《客户端实施说明》新版鉴权与端点**。
> **实现唯一来源**：`server/telemetry.ts`；实测报文样例：`docs/上报.json`；完整机制长文：`docs/上报触发与接口及上报内容.md`；服务端权威对接文档：`yanzi/docs/客户端实施说明.md`。
> **本工程只做「上报端」**——中心统计服务（接收 / 去重 / 清洗 / 看板）由独立后端实现，不在本仓库内。

---

## 1. 接口定义

| 项 | 值 |
|---|---|
| 端点（主） | `POST http://192.168.24.10:30507/api/docker-management`（内网直连，文档 §1） |
| 端点（备） | `POST https://yanzi-api.ziruxue.top/api/docker-management`（**双通道 fallback**：网络错误 / 5xx / 429 自动回落） |
| 端点覆盖 | 环境变量 `TELEMETRY_ENDPOINT`（设置后只走单通道，自建 / 联调用） |
| Content-Type | `application/json` |
| 鉴权头 | **`token: <共享token>`**（v1.50.10，应用级共享、随客户端分发，服务端比对 sha256 摘要，401 `TOKEN_INVALID`）；过渡头 `X-Telemetry-Key: <deviceId>` 保留（旧服务端兼容，新服务端忽略） |
| token 覆盖 | 环境变量 `TELEMETRY_TOKEN` |
| 超时 | 单次请求 **10 秒**（`AbortSignal.timeout`） |
| 成功判据 | HTTP 2xx（含 `deduped:true` 去抖命中）；**响应体不解析** |
| 失败策略 | 401/403 → `fatal`（不做密集重试，退回 12h 周期）；400/404/413 → 不重试不换端点；网络错误 / 5xx / 429 → 先换备用端点，两端点都失败 → **10 分钟后重试** |
| 容错铁律 | 任何失败（无权限 / 离线 / 采集失败）**不得影响主业务**，只写运行态 `telemetry-state.json` 的 `lastError` |

## 2. 上报载荷（14 个顶层字段，v1.50.10 起不再发 `deviceFile`）

```jsonc
{
  "device_uuid": "<sha256 硬件指纹>",   // 统计主键 = 主板+CPU+内存+硬盘+显卡+系统 6 维哈希
  "upapi": "install",                   // 上报类型（见 §3）
  "ts": "2026-11-01T12:00:00.000Z",     // 上报时间（ISO 8601）
  "uploadEnabled": true,                // 上传开关当前状态（服务端记录最新 opt-in）
  "installedAt": "2026-10-01T…",        // 安装时间 = 标识文件创建时间（重装/重建后为新时间）
  "app": "dockermanagementyanzi",
  "appVersion": "1.50.4",
  "os": "linux",
  "osVersion": "<发行版+版本>",
  "arch": "x64",
  "channel": "sea-linux-x64",
  "virtualized": false,                 // 是否虚拟化 / 容器环境
  "hardware": {                         // 6 维标识快照（安装时写一次，与 device_uuid 同源可复算）
    "system": "…", "cpu": "…", "gpu": "…",
    "memory": "…", "diskUid": "…", "boardSerial": "…"
  },
  "details": {                          // 富硬件明细（与「硬件信息」卡片逐项对应）
    "cpu":    { "model": "…", "cores": 8, "threads": 16, "freqGHz": 3.2 },
    "gpu":    { "model": "…", "memory": "…" },
    "memory": { "model": "…", "sizeGB": 32 },
    "disk":   { "serial": "…", "model": "…", "size": "…" },
    "dmi":    { "boardName": "…", "productSerial": "…", "productUuid": "…" }
  }
}
```

**明确不上报**：

- ❌ 容器 / 镜像 / 堆栈等任何业务数据
- ❌ 账号 / 密码 / 会话信息
- ❌ 文件内容 / 应用日志
- ❌ 公网 IP

> `hardware` / `details` 受「系统设置 → 硬件信息 → 上传硬件指纹」开关控制（关闭时报 `null`，其余字段照发）。

## 3. 触发时机与上报类型（v1.35.11 语义）

`upapi` 的**唯一判据**：当前 `device_uuid` 是否等于上次**成功**上报的 `device_uuid`（存于 `telemetry-state.json` 的 `lastDeviceId`）。

| 触发时机 | 强制发送 | upapi |
|---|---|---|
| 首次安装 / 重装 / 标识文件重建（`device_uuid` 变了） | ✅ | `install` |
| 进程启动 / systemd 重启（延迟 **30 秒**首报） | ✅ | `heartbeat`（ID 未变） |
| 每 **12 小时**周期心跳 | ❌（未到期且无需 install 时零请求） | `heartbeat` |
| 失败（网络 / 5xx）后 **10 分钟**重试 | ✅ | 同上判据 |
| 页面「立即上报」（`POST /api/telemetry/report`） | ✅ | 同上判据 |
| **上传开关切换瞬间**（用户显式操作，唯一例外） | ✅ | **恒 `install`** |

⇒ **`install` 次数 ≈ 去重后的设备数**，重启 / 周期 / 重试都不会放大安装量。

## 4. 总开关与本地状态

| 项 | 位置 / 文件 | 说明 |
|---|---|---|
| 总开关 | 系统设置 → 本机设备 →「上传安装数量统计」（`settings.telemetry.enabled`） | **默认开启**；关闭后**不发任何请求** |
| 标识文件 | `<安装目录>/config/device.info` | 创建后只读；普通卸载不清除（重装仍视为同一设备）；仅「被删」或「创建时间≠修改时间」时重建（24h 内限流 1 次） |
| 运行态 | `<安装目录>/config/telemetry-state.json` | `installReported` / `lastDeviceId` / `lastReportAt` / `lastRebuildAt` / `lastError`，每次上报后写 |
| 状态展示 | 前端「活跃度」面板（`src/components/ActivityPanel.tsx`） | 数据来自 `GET /api/telemetry/status` |

## 5. 本机侧自有接口（与中心统计无关）

| 接口 | 用途 |
|---|---|
| `GET /api/telemetry/status` | 状态卡片：上次上报时间 / 类型 / 错误 / 标识文件信息 |
| `POST /api/telemetry/report` | 手动强制上报一次（前端未接线，curl 可调） |
